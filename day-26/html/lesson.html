Topic 1 — Why Patterns?

Patterns are recurring solutions to recurring problems. They provide developers with a shared vocabulary for discussing software structure and design.

  • Patterns are not language features.
  • They are common approaches to solving problems.
  • Examples include Module, Observer, Factory, Singleton and Proxy.

Topic 2 — Module Pattern

The Module Pattern uses closures to create private data and expose a public API. 


const counter = (function () {
  let count = 0;

  function increment() {
    count++;
  }

  function get() {
    return count;
  }

  return {
    increment,
    get
  };
})();

Modern ES Modules provide the same concept using export and import.

Topic 3 — Observer Pattern (Pub/Sub)

A subject publishes events and subscribers listen for them. 


function createEmitter() {
  const listeners = new Map();

  return {
    on(event, callback) {},
    off(event, callback) {},
    emit(event, ...args) {}
  };
}

Useful for notifications, event buses and UI events.

Topic 4 — Factory Pattern

Factories create objects without exposing the creation logic to callers. 


function vehicleFactory(type) {
  switch (type) {
    case "car":
      return new Car();

    case "bike":
      return new Bike();

    case "truck":
      return new Truck();
  }
}

Factory functions can also return plain objects.

Topic 5 — Singleton Pattern

A Singleton guarantees that only one instance of an object exists. 


class Logger {
  static #instance = null;

  constructor() {
    if (Logger.#instance) {
      return Logger.#instance;
    }

    Logger.#instance = this;
  }
}

In modern JavaScript, exporting a single object from a module is often enough to create a singleton.

Topic 6 — Proxy Pattern

A Proxy intercepts operations performed on an object. 


const user = new Proxy(target, {
  get(obj, prop) {
    console.log(`reading ${prop}`);
  },

  set(obj, prop, value) {
    console.log(`setting ${prop}`);
  }
});

Common uses:

  • Validation
  • Logging
  • Access control
  • Reactive state systems

Topic 7 — Reactive Objects with Proxy

Proxies can be used to build a simple reactive system. 


function reactive(obj, onChange) {
  return new Proxy(obj, {
    set(target, prop, value) {
      target[prop] = value;
      onChange(prop, value);
      return true;
    }
  });
}

Every property update automatically triggers the supplied callback.
